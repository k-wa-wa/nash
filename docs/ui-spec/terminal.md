# ターミナル画面 (/terminal) 仕様・チェックリスト

## 1. コンポーネント構成と画面対応

NashのターミナルUIは、モバイルファーストを意識したレイアウトを採用しています。

```text
+-------------------------------------------------------+
|  Connected to server...                               |
|  $ ls -la                                             | Area: TerminalOutput
|  drwxr-xr-x  2 user  staff   64 Jan 10 12:00 .        | File: src/components/TerminalOutput.tsx
|  $ _                                                  | Desc: ログ表示とxterm端末エリア
|                                                       |
|                                                       |
|                                                       |
|                                                       |
|                                                       |
|                                                       |
+-------------------------------------------------------+
|                                                       | Area: CommandInput
|  > ls -la                        [ ↵ ]                | File: src/components/CommandInput.tsx
|                                                       | Desc: コマンド入力と送信ボタン(青色)
+-------------------------------------------------------+
|                                                       | Area: ShortcutBar
|  [ESC] [TAB] [CTRL-C] [↑] [↓] ...                     | File: src/components/ShortcutBar.tsx
|                                                       | Desc: 補助キー(常に最下部に固定)
+-------------------------------------------------------+
|                                                       |
|                      キーボード                         |
|                                                       |
|                                                       |
+-------------------------------------------------------+
```

## 2. コンポーネント詳細仕様

### TerminalOutput (`src/components/TerminalOutput.tsx`)
- [ ] **役割**: `xterm.js` インスタンスの生成と管理を行うこと
- [ ] **データ描画**: バックエンドからのログデータを正確に描画すること
- [ ] **リサイズ**: リサイズイベントを検知し、適切にハンドリングすること
- [ ] **バッファ監視**: ターミナルのバッファモード（通常 / 代替画面）を監視し、`onBufferChange` コールバックを通じて親コンポーネントに通知すること
- [ ] **Props内容**:
    - `onData(data: string)`: ユーザー入力をバックエンドへ送信
    - `onResize(cols, rows)`: リサイズ情報を通知
    - `onBufferChange(isAlt: boolean)`: バッファ状態の変更を通知

### CommandInput (`src/components/CommandInput.tsx`)
- [ ] **役割**: コマンドライン入力のインターフェースを提供すること
- [ ] **入力要素**: テキストボックスと送信ボタンを提供すること
- [ ] **フォーカス制御**: `autoFocus` と `ref.focus()` により適切に入力フォーカスを制御すること
- [ ] **デザイン**: Glassmorphism（すりガラス）スタイルの背景であること
- [ ] **ボタン**: 右端に青色の送信ボタン (`CornerDownLeft` アイコン) があること
- [ ] **送信挙動**: `value` が空でも送信可能（改行コード送信）であること
- [ ] **Props内容**:
    - `value`: 入力中の文字列
    - `onChange`: 入力更新ハンドラ
    - `onEnter`: 送信アクションハンドラ
    - `visible`: 表示/非表示フラグ

### ShortcutBar (`src/components/ShortcutBar.tsx`)
- [ ] **役割**: モバイル端末で入力しにくいキー（ESC, TAB, CTRL, 矢印キー）へのクイックアクセスを提供すること
- [ ] **配置**: 横スクロール可能なバーとして画面最下部に常駐すること
- [ ] **デザイン**: 入力エリアと同じGlassmorphismスタイルであること
- [ ] **操作性**: ボタンはタップしやすいサイズに調整されていること

## 3. 初期化・接続プロセス
- [ ] **WebSocket接続**: 画面遷移時に `/ws` への接続が開始されること
- [ ] **パラメータ送信**: 以下のクエリパラメータが正しく送信されること
    - `host`, `user`, `port`, `pass`, `identity_file`
- [ ] **接続成功表示**: 接続確立時、ターミナル内に "Connected to server." と表示されること
- [ ] **エラー表示**: 接続失敗時（WebSocket error/close）、適切なエラーメッセージが表示されること
- [ ] **ページタイトル**: ブラウザのタイトルが `{host} - nash` に更新されること

## 4. 認証プロセス
- [ ] **パスワード要求検知**: サーバーから `AUTH_REQUIRED` メッセージを受信した際、`PasswordModal` が表示されること
- [ ] **PasswordModal 挙動**:
    - [ ] モーダル表示時にパスワード入力欄に自動フォーカスが当たること
    - [ ] パスワード入力・送信で再接続が試行されること
    - [ ] Cancelボタン押下でホーム画面に戻ること
- [ ] **SSH鍵認証**: `identity_file` パラメータによる公開鍵認証が機能すること

## 5. 通常モード (Shell Mode)
- [ ] **レイアウト**:
    - [ ] `TerminalOutput` が上部に表示されること
    - [ ] `CommandInput` (Glassmorphismスタイル) が下部に入力バーとして表示されること
    - [ ] `ShortcutBar` が最下部に固定されていること
- [ ] **フォーカス制御**:
    - [ ] 接続完了直後、`CommandInput` に自動フォーカスが当たること
    - [ ] ターミナル領域のクリックで `CommandInput` にフォーカスが戻ること
    - [ ] 送信後もフォーカスが維持されること
- [ ] **送信挙動**: Enterキーまたは青色の送信ボタン押下でコマンドが送信され、入力欄がクリアされること

## 6. インタラクティブモード (Application Mode)
- [ ] **検知**: `vim`, `top`, `less` 等による Alternate Buffer 切り替えを検知すること
- [ ] **レイアウト変更**:
    - [ ] `CommandInput` が非表示になること
    - [ ] `TerminalOutput` が `ShortcutBar` 直上まで拡張され、領域を最大化すること
- [ ] **ShortcutBar 連携**:
    - [ ] 通常モード: [Enter] キーはコマンド送信として機能
    - [ ] インタラクティブモード: [Enter] キーは純粋な改行コード (`\r`) として送信
- [ ] **復帰**: アプリケーション終了時、自動的に通常モードのレイアウト（`CommandInput` あり）に戻ること

## 7. モバイル・レスポンシブ対応
- [ ] **Visual Viewport**: ソフトウェアキーボード表示時、`visualViewport` のリサイズに合わせてレイアウトが調整され、入力欄や `ShortcutBar` が隠れないこと
- [ ] **スクロール管理**: 全体の画面スクロール（Bodyスクロール）が抑制され、固定レイアウトが維持されていること
- [ ] **TerminalOutput**: ターミナル内のスクロールがスムーズに行えること。また、コマンド入力時やショートカットキー押下時に最新の出力まで自動的にスクロールされること
- [ ] **ShortcutBar**: 横スクロールで全ての補助キー（ESC, TAB, CTRL, 矢印等）にアクセスできること
